Creación del repositorio remoto y trabajo en equipo

Inicio del proyecto

Para iniciar un proyecto grupal, una de las personas del equipo debe encargarse de crear el repositorio en GitHub e invitar al resto de integrantes y al equipo docente.

1 Creación del repositorio

  1. Accede a GitHub e inicia sesión con tu cuenta corporativa.
  2. Haz clic en el botón New (Nuevo repositorio).
  3. Escribe el nombre del repositorio para la práctica o proyecto.
  4. Importante: Mantén el repositorio completamente vacío (no marques las casillas para añadir README, .gitignore o License).
  5. Haz clic en Create repository.

2 Añadir colaboradores

  1. En la página de tu repositorio recién creado, entra en Settings.
  2. En el menú lateral, selecciona Collaborators.
  3. Haz clic en el botón Add people.
  4. Introduce el correo o usuario de GitHub de los miembros del grupo y del profesorado e invítalos.
  5. Las personas invitadas deberán aceptar la invitación recibida por correo o notificación en GitHub.

Identificación de la autoría de los commits

Configura en Eclipse los datos de identificación que se asociarán a tus aportaciones al proyecto para que se atribuyan correctamente en GitHub:

Window > Preferences > Team > Git > Configuration (o Preferences > Git > User)

Añade o verifica las entradas user.name (tu nombre completo) y user.email (usa la dirección @opendeusto.es registrada en GitHub).

Conexión mediante Token de Acceso Personal (PAT)

Método estándar para la asignatura

Para simplificar el acceso y evitar problemas de configuración con claves locales, utilizamos la conexión HTTPS autenticada mediante un Token de Acceso Personal (PAT). GitHub no permite usar tu contraseña habitual para operaciones de Git; en su lugar usarás este token.

Pasos para generar tu Token de Acceso en GitHub

  1. En GitHub, entra en tu foto de perfil (esquina superior derecha) y selecciona Settings.
  2. En el menú lateral izquierdo, pulsa en Developer settings (al final del menú).
  3. Navega a Personal access tokens > Tokens (classic).
  4. Haz clic en Generate new token > Generate new token (classic).
  5. En Note, escribe un nombre descriptivo (ej. Eclipse Deusto Token).
  6. Establece una fecha de caducidad (se recomienda la duración del cuatrimestre).
  7. Marca la casilla del scope principal repo (esto seleccionará los permisos necesarios para gestionar repositorios).
  8. Desplázate al final y haz clic en Generate token.

Importante:

Copia y guarda el token generado inmediatamente en un lugar seguro. GitHub no volverá a mostrártelo una vez abandones la página. Usarás este token como tu contraseña siempre que Eclipse te solicite credenciales para GitHub.

Publicar un proyecto de Eclipse en GitHub

1 Vincular repositorio local

Haz clic derecho sobre el proyecto > Team > Share Project.

Marca la casilla "Use or create repository in parent folder of project", selecciona el proyecto, pulsa Create Repository y finaliza con Finish.

2 Creación del fichero .gitignore

Antes de realizar el primer commit, crea un archivo de texto llamado .gitignore en la carpeta raíz de tu proyecto. Este fichero evita subir archivos compilados y configuraciones locales que suelen provocar conflictos entre los miembros del equipo.

Contenido recomendado para .gitignore 
# Código compilado
*.class
/bin/

# Eclipse
.metadata/
.settings/
.project
.classpath

# IntelliJ IDEA
.idea/
*.iml

# VS Code
.vscode/

# Ficheros de SQLite
*.db
*.db-journal

# Ficheros del sistema operativo
.DS_Store
Thumbs.db
3 Primer commit local

Puedes acceder a la vista de confirmación de dos formas equivalentes:

  • Haciendo clic derecho sobre el proyecto y seleccionando Team > Commit...
  • O abriendo directamente el panel Git Staging.
  1. Arrastra tus clases .java, recursos y el fichero .gitignore recién creado a Staged Changes.
  2. Escribe un mensaje explicativo (ej: "Initial commit").
  3. Pulsa el botón Commit (para el primer commit del repositorio).
¿Por qué no pulsar 'Commit and Push' la primera vez?
Al ser el primer commit, el repositorio local aún no conoce la URL remota HTTPS de GitHub. Si pulsas Commit and Push se producirá un error por falta de origen configurado (Upstream).
4 Primer push a GitHub

Haz clic derecho sobre el proyecto > Team > Push HEAD...

  • Copia la URL HTTPS de tu repositorio de GitHub (se obtiene desde el botón verde Code en GitHub) y pégala en el campo URI.
  • En el campo User introduce tu nombre de usuario de GitHub.
  • En el campo Password pega tu Token de Acceso Personal (PAT). Marca la casilla para guardar credenciales.
  • Asegúrate de que la rama remota coincide (main o master).
  • Pulsa Push. A partir de este momento ya podrás utilizar directamente el botón Commit and Push o Team > Push to Upstream para futuras entregas.

Importación de un proyecto desde GitHub

Importante: Al no subir la configuración propia de Eclipse (gracias al .gitignore), debes importar mediante Smart Import:
File > Import > Projects from Git (with smart import) > Clone URI

Pega la URL HTTPS del repositorio. Introduce tu usuario de GitHub y tu Token PAT cuando se soliciten credenciales.

Configuración como proyecto Java tras la importación:

Si tras importar el proyecto Eclipse no lo detecta automáticamente como un proyecto de Java (debido a que los archivos de entorno fueron omitidos por el .gitignore), haz clic derecho sobre el proyecto en el explorador de paquetes y selecciona:

Configure > Convert to Java Project

Rutina para coordinar el trabajo y minimizar conflictos

Para minimizar la aparición de conflictos al trabajar en equipo, sigue este orden en cada sesión de trabajo:

PASO 1

PULL (al empezar)

Descarga los cambios enviados por el resto del equipo antes de programar.

Team > Pull
PASO 2

CÓDIGO Y COMMIT

Desarrolla tus tareas realizando commits frecuentes.

Team > Commit...
PASO 3

PULL (antes de subir)

Sincroniza de nuevo por si se han publicado cambios mientras programabas.

Team > Pull
PASO 4

PUSH

Envía tus commits al repositorio remoto en GitHub.

Team > Push to Upstream

Gestión y resolución de conflictos

Un conflicto ocurre cuando dos personas modifican la misma línea de código en un archivo y Git no puede determinar automáticamente cuál prevalece.

Desmitificando las marcas de conflicto en el código fuente Editor de texto / Eclipse

Si abres un archivo en conflicto sin usar una herramienta gráfica, verás estas marcas escritas directamente en tu código Java. ¡No te asustes! Este es su significado:

// Código previo sin conflictos
<<<<<<< HEAD (Tus cambios locales)
System.out.println("Hola desde mi ordenador local");
======= (Línea separadora)
System.out.println("Hola desde la versión subida a GitHub");
>>>>>>> commit_hash (Cambios remotos de GitHub)
// Continuación del método
1. Parte superior: Tu versión local (lo que tenías escrito en tu equipo antes de hacer Pull).
2. Separador (=======): Divide ambas versiones alternativas.
3. Parte inferior: La versión remota que proviene de GitHub.

Resolución mediante la herramienta gráfica Merge Tool de Eclipse:

  1. Haz clic derecho sobre el archivo en conflicto (marcado con un icono rojo en el explorador) > Team > Merge Tool.
  2. Se abrirá un editor doble: la parte izquierda muestra tu código local y la derecha la versión de GitHub.
  3. Utiliza los botones con flechas en la barra superior para copiar los cambios válidos de un lado a otro o edita manualmente el resultado.
  4. Guarda el archivo resuelto (Ctrl + S).
  5. Abre la ventana de commit mediante Team > Commit... o el panel Git Staging, arrastra el archivo a Staged Changes, añade un mensaje (ej: "Conflictos resueltos") y haz Commit and Push.
